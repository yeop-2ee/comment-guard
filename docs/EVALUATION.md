## 4. 서비스 목적 기준 평가 (심각도와 필터)

### 4.1 기준값 조정 (valid)

| 기준값 | valid 정상 오차단율 | valid 혐오 차단율 | 비고 |
|---|---|---|---|
| 시작값 30 / 60 | **65.0%** | 50.8% | 정상 댓글 셋 중 둘을 가림. 사용 불가 |
| **조정값 51 / 55** | 14.6% | 60.7% | 명세서 2.1장 규칙으로 선택 |

시작값이 실패한 이유는 공식 `100 × (P(hate) + 0.5 × P(offensive))`에 있습니다. 정상 댓글도 offensive 확률을 어느 정도 받기 때문에 점수가 30을 쉽게 넘습니다. valid 정상 댓글 점수의 중앙값이 36점이고, 상위 10%는 54점 이상입니다. 조정 규칙은 두 목표(오차단율 ≤ 15%, 차단율 ≥ 60%)를 먼저 만족시키고, 그 안에서 등급과 라벨이 가장 잘 맞는 조합을 고릅니다.

**대가:** 주의 구간이 51~54점으로 좁습니다. eval에서 주의 등급은 43건(9%)뿐이고, 대부분 일반(292건)이나 심각(136건)으로 나뉩니다. medium의 "흐리게" 처리가 실제로 적용되는 경우가 적다는 뜻입니다.

### 4.2 eval 결과

| 민감도 | 혐오 차단율 (hide) | 정상 오차단율 (blur + hide) |
|---|---|---|
| low | 59.8% [51.0, 68.1] | 3.8% [1.7, 7.9] |
| **medium** | 59.8% [51.0, 68.1] | 8.1% [4.8, 13.4] |
| high | 73.8% [65.3, 80.8] | 8.1% [4.8, 13.4] |

- low와 medium의 차단율이 같은 이유: 두 민감도 모두 "심각"만 숨기고, medium은 "주의"를 흐리게 처리할 뿐이기 때문입니다.
- eval의 정상 오차단율(8.1%)이 valid(14.6%)보다 낮습니다. valid 값은 eval의 95% 구간 [4.8, 13.4] 밖에 있어서, eval 표본의 변동만으로는 설명하기 어렵습니다. 두 분할의 정상 댓글 분포가 다를 가능성이 있지만 원인은 확인하지 않았습니다. 다른 데이터에서는 오차단율이 valid 수준(약 15%)까지 올라갈 수 있다고 보는 편이 안전합니다.
- **등급 순서 일치도:** 정답 순서(none < offensive < hate)와 심각도 점수의 스피어만 ρ = **0.641** (p < 1e-50). 점수가 실제 심각한 순서를 상당히 반영합니다.

## 5. 잘못된 결과 1건 분석

eval에서 놓친 혐오(정답 hate, 예측 none)는 15건입니다. 그중 P(none)이 높은 순으로 5건을 `error_candidates.json`에 남겼고, 가장 원인이 분명한 1건을 분석합니다.

| 항목 | 내용 |
|---|---|
| eval 행 | 223 |
| 원문 (가림) | `세* 인성ㅆㅎ**인거 같은데 왜 알면서도 사귀는걸까 대*인가...흠` |
| 정답 | `hate`, bias = `gender` |
| 예측 | `none` (P = none 0.503 / offensive 0.361 / hate 0.136), 심각도 32점 → 일반, medium에서 **보이기** |

**영향을 준 n-gram** (TF-IDF 값 × (hate 계수 − none 계수)):
- hate 쪽: `면서`(+0.139), `같은`(+0.091), `인성`(+0.075). 모두 일반적인 단어입니다.
- none 쪽: ` 같은`(−0.057), `인가.`(−0.054), `사귀`(−0.051).

**원인:**
1. **초성 비속어가 어휘 사전에 전혀 없습니다.** `ㅆㅎ**`는 train_fit에 한 번도 나오지 않습니다. 그 일부인 `ㅎ**`, `**`도 1번씩만 나와서 `min_df=2`에 걸려 사전에서 빠졌습니다. 이 댓글에서 가장 모욕적인 부분이 모델에게는 "없는 글자"입니다.
2. **성적 비하가 맥락에 의존합니다.** `대*`는 사전에 있지만 train_fit에 2번(hate 1, none 1)만 나와서 가중치가 거의 없습니다. 연애 관계를 성적으로 비하하는 의미는 단어 하나가 아니라 문장 전체("왜 알면서도 사귀는걸까 … 인가")에서 나옵니다. 글자 n-gram 선형 모델은 이걸 잡지 못합니다.
3. 남은 단어(`인성`, `같은데`, `사귀는걸까`)는 정상 댓글에도 흔해서 none 쪽으로 기울었습니다.

**개선 아이디어:**
- 초성 표기를 그대로 학습할 수 있게 사전학습 모델(KcELECTRA는 실제 댓글로 사전학습해서 초성·변형 표기에 상대적으로 강함)을 쓰고, 이 사례가 고쳐지는지 M6에서 확인합니다.
- `min_df`를 1로 낮추는 실험(valid로만 판단). 사전이 커지고 과적합 위험이 늘어나는 trade-off가 있습니다.
- 초성 비속어 사전으로 데이터를 증강합니다. 신조어가 계속 생기기 때문에 유지보수 비용이 듭니다.

### 5.1 서비스 사용 중 발견한 오판: 신조어 칭찬을 혐오로 판정 (2026-11-10)

eval 밖에서, 웹 화면을 써보다가 사용자가 발견한 사례입니다(직접 만든 예시 문장).

| 항목 | 내용 |
|---|---|
| 입력 | `ㅇㅈ 이번 곡 개좋음 👍👍` (뜻: "인정, 이번 곡 정말 좋음") |
| 기대 | 정상 (칭찬) |
| 예측 | 혐오 (P = 정상 0.327 / 공격 0.176 / 혐오 0.498), 심각도 59점 → 심각, medium에서 **가림** |

영향을 준 n-gram과 train_fit에서의 분포:

| n-gram | train_fit 분포 | hate − none 기여 |
|---|---|---|
| ` 개` | '개'+한글이 들어간 352건 중 hate 45%, none 27%. 대부분 욕설 접두어로 쓰임 | +0.524 (가장 큼) |
| `ㅇㅈ` | 9건 중 hate 78%, none 0건 | +0.16 ~ +0.26 |
| 👍 | 0건 | 정보 없음 |

**원인:** '개'를 강조 접두어로 쓴 긍정 표현(개웃김, 개멋있다 등)은 train_fit에 15건뿐이고, 그중 절반은 악플 문장 안에 섞여 있습니다. 글자 n-gram 선형 모델은 '개'가 접두어로 쓰였는지 욕설로 쓰였는지 문맥으로 구분하지 못하고, 표본이 적은 `ㅇㅈ`에는 우연한 상관이 그대로 가중치로 남았습니다. 5장 사례(초성 비속어를 놓침)와 방향만 반대이고 원인은 같습니다. 표면 글자에만 의존하기 때문입니다.

**하지 않은 것:** 이 문장만 정상으로 바꾸는 규칙이나 금지어 예외를 넣지 않았습니다. eval로 검증되지 않은 땜질이고, 같은 유형의 다른 문장은 고치지 못하기 때문입니다.

**대응 계획:** 같은 유형의 문장을 모은 행동 검사 세트(직접 만든 예시, 학습·조정에 쓰지 않음)로 오판 비율을 수치로 재고, 사전학습 모델(M2, KcELECTRA)과 비교합니다.

**결과 (8장):** 행동 검사 세트에서 M1은 '개' 강조 칭찬 6문장 중 5문장을 맞혔고, 틀린 1문장이 바로 이 문장이었습니다. 문제가 같은 유형 전반이 아니라 짧은 문장에 위험 조각이 몰린 경우에 한정된다는 뜻입니다. 다만 M1이 맞힌 칭찬 문장들도 40~45점으로 주의 기준(51점)에 가까웠습니다. M2는 이 문장을 정상(P = 0.984, 심각도 1점)으로 판정했고, 행동 검사 42문장을 모두 맞혔습니다.

## 7. 측정하지 못한 부분과 한계

- 연예 뉴스 댓글만 다룹니다. 게임·정치·SNS 등 다른 영역의 성능은 측정하지 않았습니다.
- 데이터 수집 시점(2020년 이전) 이후의 신조어와 변형 욕설에는 약할 수 있습니다. 5.1장 사례(M1)가 그 예입니다.
- 혐오와 공격적 표현의 경계는 라벨링한 사람마다 다를 수 있습니다. offensive의 낮은 F1에는 라벨 자체의 불확실성도 섞여 있을 수 있지만, 따로 측정하지는 않았습니다.
- eval이 471건이라 구간이 넓습니다. 특히 혐오 차단율 목표(60%)의 달성 여부는 판정할 수 없습니다.
- 편향 하위 그룹은 60여 건씩이라 그룹 간 차이도 불확실합니다.
- 확률 보정(calibration)은 측정하지 않았습니다. `class_weight="balanced"` 때문에 확률이 실제 비율과 다를 수 있고, 이것이 시작 기준값이 실패한 원인 중 하나로 보입니다.
- 지연과 메모리는 맥 로컬에서만 쟀습니다(8.5장). Vercel에서의 지연과 cold start는 아직 재지 않았습니다.
- 행동 검사 세트는 한 사람이 만든 42문장과 36문장입니다. 유형별 경향을 보는 용도이고 통계적 결론은 아닙니다.
- 사용자 만족도, 민감도 단계가 적절한지, 리포트가 법적으로 유용한지는 측정하지 않았습니다.
- **서빙 모델(M2)은 암시적 성희롱과 비꼼을 자주 놓칩니다** (행동 검사 v2: 성희롱 1/6, 비꼼 0/6, 8.4.1장). 노골적인 단어가 없는 성적 대상화 댓글은 medium에서도 보일 수 있습니다.

### 8.4.1 행동 검사 v2: 혐오 수준 문장 (36문장, `runs/20261110-010956-probe-behavior_v2/probe_metrics.json`)

M2로 바꾼 뒤 웹 화면 예시에서 심각 등급이 거의 나오지 않는다는 지적이 있어서 확인했습니다.

**원인 1, 예시가 혐오 수준이 아니었음.** 데이터셋 라벨링 가이드는 hate를 "성별·집단을 향한 공격, 사회적 지위를 크게 해치는 모욕, 성희롱"으로, offensive를 "무례, 욕설, 비꼼"으로 나눕니다. 기존 예시 대부분("꼴보기 싫다", "은퇴해라")은 offensive에 해당하고, M2는 이를 공격 → 주의로 판정했습니다. M1은 같은 문장을 심각으로 판정했는데, 이는 M1의 과잉 판정이었습니다. eval에서 정답이 hate인 댓글의 M2 점수는 중앙값 90점이라, 심각 등급 자체는 정상적으로 작동합니다.

**그래서 v2를 만들었습니다.** v1과 같은 원칙으로, 결과를 보기 전에 작성하고 해시로 고정했습니다(커밋 `1b9e784`). 가이드의 hate 정의에 맞는 4유형은 심각, offensive 정의에 맞는 2유형은 주의를 기대합니다.

| 유형 | 기대 등급 | M1 | M2 |
|---|---|---|---|
| 성별 혐오 | 심각 | 6/6 | 6/6 |
| 기타 집단 혐오 (국적·지역·나이·장애) | 심각 | 3/6 | 5/6 |
| 강한 모욕 | 심각 | 5/6 | 4/6 |
| 성희롱 | 심각 | 2/6 | **1/6** |
| 단순 무례 | 주의 | 1/6 | 3/6 |
| 비꼼 | 주의 | 0/6 | **0/6** |
| 등급 일치율 | | 47% (17/36) | 53% (19/36) |
| 심각이어야 할 문장 중 심각 | | 67% (16/24) | 67% (16/24) |
| 심각이어야 할 문장이 medium에서 그대로 보임 | | 17% (4/24) | 12.5% (3/24) |
| 무례한 수준을 심각으로 과잉 판정 | | 17% (2/12) | 0% (0/12) |

**발견한 약점 (M2):**
1. **암시적 성희롱을 놓칩니다.** `가슴만 보이네 ㅋㅋㅋ`(정상 0.97), `다리 보려고 이 방송 본다 ㅎㅎ`(정상 0.97), `몸매 보니까 밤에 생각나네 ㅎㅎ`(정상 0.80)는 medium에서도 **그대로 보입니다.** train_fit에 '가슴'은 17건, '몸매'는 31건뿐이고, '가슴 아프다'처럼 정상 문맥도 섞여 있어 학습할 근거가 부족합니다. 반면 `벗으면 더 잘 팔릴 듯`은 혐오 0.94로 잘 잡았습니다.
2. **비꼼은 두 모델 모두 놓칩니다(0/6).** `기자님 소설 잘 쓰시네요`처럼 겉으로는 긍정 표현이라, 문장만 보고는 판단하기 어렵습니다.
3. **집단 혐오·강한 모욕의 일부가 기준선 바로 아래에 걸립니다.** `동남아 사람들 수준이 다 그렇지` 67점, `인간 쓰레기는 사회에서 격리해야 함` 69점(심각은 70점부터). 주의로 흐리게는 처리됩니다.
4. **공격이 가장 높은 확률이어도 일반 등급이 될 수 있습니다.** `노래 진짜 못하네 귀 아프다`는 공격 0.56이지만, 점수 공식이 공격을 절반만 반영해서(`100 × (혐오 + ½ × 공격)`) 28점 → 일반입니다. 주의 기준 39점에 닿으려면 공격 확률이 약 0.78 이상이어야 합니다.

**하지 않은 것:** 이 결과를 보고 기준값이나 공식을 바꾸지 않았습니다. v2는 직접 만든 36문장이라, 여기에 맞추면 작성자 한 명의 판단에 과적합되고 valid로 정한 규칙이 무너집니다. 위 약점은 한계로 기록하고(7장), 바꾼다면 valid에서 다시 검증한 뒤 바꿔야 합니다.

|---|---|---|---|
| valid hate macro-F1 향상 | ≥ +0.02 | +0.134 | 통과 |

**대가와 대응:**
- 모델이 437MB라 함수가 새로 시작할 때 모델을 받는 시간(콜드 스타트)이 길어집니다. torch는 함수 크기 한도를 넘어서 서빙은 ONNX로 합니다. M4에서 실측해서 기록합니다.
- Vercel 함수 메모리는 2GB(Hobby 최대)로 둡니다. PyTorch는 함수 크기 한도(500MB)를 넘어서, 클라우드에서는 M2를 ONNX로 변환해 onnxruntime으로 실행합니다(M4).
- M1은 비교 기준과 대체 모델로 남깁니다. 같은 API로 `MODEL_URI`만 바꾸면 M1로 돌아갈 수 있습니다.
